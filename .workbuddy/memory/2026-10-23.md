- `main__bottom_nav.xml` 三入口；`MainActivity.PAGE_COUNT 3 → 2`；

  - 标签用 `getChildFragmentManager()` + `hide()/show()` 保活，
    每个标签是一个 `DocumentEditAndViewFragment`，切回来光标/滚动/未保存文字都在。

  - 关闭有改动的标签弹「保存 / 不保存 / 取消」。
- `AppSettings` 新增：`getEditorStartupMode()`、`getEditorOpenTabs/setEditorOpenTabs`、
  `getEditorRecentFiles/addEditorRecentFile`、`getEditorLastFile/setEditorLastFile`、
  `getEditorTabsViewMode`、`isEditorTabsPanelExpanded`、`isEditorTabsGroupCollapsed`。
- `GsFileBrowserFragment` 加 `getRecyclerView()`，供 MainActivity 挂滚动监听。
- MainActivity：`openInEditor(file)`（文件页点文件不再另开 Activity）、
  `setupKeyboardChromeAutoHide()`（可见高度差 > 120dp）、
  `setupFileListChromeAutoHide()`（RecyclerView dy，挂 `R.id.tag_chrome_scroll` 防重复）。

### 踩的坑（重要）
1. **`setInt` 与 `getIntOfStringPref` 不配对**：`setInt(keyRes,v)` 存的是 int 型，
   而 `getIntOfStringPref` 读的是 string 型（`getString` 抛 ClassCastException 后返回默认值）。
   结果"切方块视图"点了没反应。→ 要么都用 `setInt/getInt`，要么都用 `setString/getIntOfStringPref`。
2. **编辑器 `onPause()` 会自动 `saveDocument(false)`**：所以关标签选"不保存"其实还是会写盘。
   → 新增 `DocumentEditAndViewFragment.discardUnsavedChanges()`：先把编辑区内容退回磁盘版本、
   `resetChangeTracking()`，再移除片段，`saveDocument` 就变成空操作。
3. **`GsFileBrowserFragment._toolbar = activity.findViewById(R.id.toolbar)`** 是全局工具栏，
   它会把选择计数 `(1 / 4)` 写进副标题并留在编辑页上。→ `onViewPagerPageSelected` 离开文件页时 `setSubtitle(null)`。
4. 打开文件后标题可能被 `updatePageTitle()` 抢先写成上一个文件名 → `openInEditor` 里
   `openFile()` 之后立刻再 `updatePageTitle()` 一次；`onEditorTabChanged` 去掉 `getCurrentItem` 判断。
5. `RecyclerView` 不支持 `android:maxHeight` → 写了 `MaxHeightRecyclerView`（onMeasure 截断）+ `attrs.xml`。
6. MuMu 上的 `exec-out screencap` 会返回上一帧（连按两次截图 md5 相同）；
   要么 `screencap -p /sdcard/x.png` 再 pull，要么用 `uiautomator dump` 看真实层级。
   另外 `input swipe` 触发不了 ViewPager2 翻页（`mTouchSlop*4`），
   要用 `input motionevent DOWN/MOVE.../UP` 模拟真实拖动。

## 第二轮：改成「文件 / 编辑 / 最近 / 设置」四入口三页面

### 最终结构（用户两次纠正后的定论）
- 底部导航 4 个入口：**文件、编辑、最近、设置**。
  - `nav_notebook` → 文件页（唯一能新建文件的地方，FAB）
  - `nav_editor` → 编辑页，**纯文本编辑区**，没有标签条/文件列表/新建按钮
  - `nav_tabs` → 最近页（字符串值是"最近"，内部类名仍叫 `EditorTabsFragment`）
  - `nav_settings` → 不是页面，`animateToActivity(SettingsActivity)` 后 `return false`
- ViewPager 仍是 3 页（`PAGE_COUNT = 3`），设置不进 pager。
- 「固定文件 / 最近文件」两组只在**最近页**里；编辑页什么都不显示。

### 新增/重写的文件
- `activity/EditorFragment.java`（新）：持有 `List<Tab>`，import 了 `restoreTabs/saveTabs`
  （prefs：`pref_key__editor_tabs`，格式 `pinned|path` 每行一条）、`MAX_TABS = 8`。
  对外 API：`getTabs/getCurrentFile/hasOpenTabs/indexOfPath/isDirty/openFile/requestClose/
  setPinned/swapTabs/hideKeyboard/setPageVisible`。
- `activity/EditorTabsFragment.java`（新，「最近」页）：只读 `EditorFragment` 的数据，
  700ms 轮询 + signature 比对，结构没变只 `updateDirty`，变了才 `rebuild`。
- `frontend/EditorTabsAdapter.java`：`TYPE_HEADER/TYPE_TAB/TYPE_RECENT`，`GRID_OFFSET=10`
  区分两种 `getItemViewType`；`Item.selected` 表示"当前正在编辑"。
- 布局：`editor__editor.xml`（纯编辑区 + 空态）、`editor__tabs_page.xml`、
  `editor__tabs_header.xml`、`editor__tabs_row.xml`、`editor__tabs_card.xml`；
  drawable `bg_editor_row.xml`（activated → `m3_secondary_container` 12dp 圆角）、`bg_editor_card.xml`。
- 已删除：`EditorWorkspaceFragment.java`、`editor__workspace.xml`、`bg_editor_panel.xml`、`bg_editor_tab.xml`。

### 本轮修的三个坑（都很隐蔽）
1. **冷启动直接点「最近」是一整页空白**。
   根因：原版的 `SectionsPagerAdapter` 懒加载用"占位 Fragment + `getItemId` 变化 +
   `notifyItemChanged`"在同一帧里换真身，新加的第三页来不及换。
   → 干脆去掉占位机制：`createFragment` 永远返回真实 Fragment，删掉
   `getItemId/containsItem` 的 override 和 `_realized` 数组；`ensureRealized` 换成
   `bindFragmentRef(pos)`（按 FragmentStateAdapter 的 tag 规则 `"f" + itemId` 用
   `findFragmentByTag` 补引用，防止系统回收后重建时引用为 null）。
2. **切到「最近」页后，标题栏还挂着编辑页的撤销/重做/保存/预览/搜索**。
   根因：`EditorFragment` 内部的标签 Fragment 仍然 attach，FragmentManager 合并菜单时会算上它。
   → `EditorFragment.setPageVisible(boolean)`：`frag.setMenuVisibility(visible)` +
   `invalidateOptionsMenu()`；`showTab` 里改用 `setMenuVisibility(_pageVisible && i == index)`。
   `MainActivity.onViewPagerPageSelected` 和它里面那个 `post{}` 都调一次。
3. **最近页的"当前文件"不高亮**。
   根因：`editor__tabs_row.xml` 根布局背景写的是 `?attr/selectableItemBackground`，
   根本没引用 `bg_editor_row`，`setActivated()` 自然没有视觉反馈。
   → 改成 `@drawable/bg_editor_row`，并在 selector 里补 `state_pressed` 当点击反馈。

### 顺手改的
- 方块视图的分组头宽度溢出（右侧计数被切）：item 各自加 `layout_marginHorizontal` 在
  GridLayoutManager 里算不准 → 统一挪到 RecyclerView 的 `paddingHorizontal="8dp"`。
- 卡片内布局重排：顶部一行「圆点 … 星标 ×」，下面文件名（`gravity="bottom"`），高度 88dp。
- 选中卡片描边 1.5dp → 1dp，没那么扎眼。
- **「只要页面上滑一律隐藏底栏」**：原来只监听 ScrollView 的 `onScrollPositionChanged`，
  内容不满屏时根本不产生滚动。→ `MainActivity.dispatchTouchEvent` 里加了竖手势兜底
  （`_swipeDownX/_swipeDownY/_swipeTracked`，slop 24dp，横竖比 < 1.5 才算翻页），
  上滑 `setBottomNavAutoHidden(true)` 并在 `_keyboardShown` 时顺手收键盘，下滑放回来。

- 列表 ↔ 方块切换 ✔；方块视图计数完整、卡片对齐 ✔

## 15:20 MuMu 实测：最近页拖动断触 / 返回键崩溃（两个真 bug）

### 用户反馈 → 根因（都是老代码的雷，不是手柄本身）
1. **拖一半自己松开**：`EditorTabsFragment.refresh()` 每 700ms 轮询一次，判断条件
   `if (!force && !_dragActive && signature.equals(_lastSignature))` —— 想表达"拖动时别重建"，
   但 `_dragActive==true` 时整个 if 不成立，反而**每次轮询都走 rebuild → notifyDataSetChanged**，
   把 ItemTouchHelper 手里的 viewHolder 重绑掉，拖动当场断。已改为 `_dragActive` 时直接 return。
2. **松手直接崩溃**（logcat 15:00:43）：`clearView` 是在 ItemTouchHelper 回收动画结束回调里跑的，
   那一刻 RecyclerView 正在布局，同步 `refresh(true) → notifyDataSetChanged` 抛
   "Cannot call this method while RecyclerView is computing a layout"。已改成 `rv.post()` 到下一帧。
3. **拖动粘住**：`onMove` 用的 `getAdapterPosition()` 在有待处理更新时返回 -1 → onMove 返回 false。
   换成 `getAbsoluteAdapterPosition()` + NO_POSITION 保护。
4. **设置页/最近页按返回键闪退**（logcat 15:08:00）：`MainActivity.onKeyDown` 把
   `getPosFragment(pos)`（非 0 页返回 null）直接传给 `MarkorBaseActivity.onReceiveKeyPress`，
   里面不判空就调 `fragment.onReceiveKeyPress`。加了判空 —— 这解释了"为什么以前只有文件页敢按返回键"。
