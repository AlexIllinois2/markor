### 坑 1：构建卡死在配置阶段（耗时 25+ 分钟无输出）
- 现象：日志只有 "Configuration on demand is an incubating feature." 后无进展。
- 定位手段：`jstack <daemon-pid>`（pid 用 `./gradlew --status` 查，注意 BUSY 那个），
  工作线程栈停在 `NioSocketImpl.timedFinishConnect` → `HttpClientHelper.performHttpRequest`，即 HTTPS 连接挂死。
- 根因：`maven.google.com` 在本网络完全不通（DNS 解析到 142.250.73.78，TCP 连接无限挂起，curl 25s 超时无响应）。
  项目 build.gradle 里声明了该仓库，解析新依赖时就会卡住。
- 修复：根 build.gradle 两处 `maven { url 'https://maven.google.com' }` 改为
  `maven { url 'https://dl.google.com/dl/android/maven2/' }`（官方现行地址，实测 200）。
- 另：`GRADLE_OPTS="-Dorg.gradle.internal.http.connectionTimeout=15000 -Dorg.gradle.internal.http.socketTimeout=60000"` 作为保险，实测未能让挂起的连接快速失败，真正有效的是换仓库地址。
- 排查时的误判：一度以为离线缓存够用，`--offline` 会直接报 "No cached version of com.vladsch.flexmark:flexmark-ext-ins"，说明依赖有更新，必须联网。

### 坑 3：git clone 报「类找不到 com.jcraft.jsch.DHEC256」（18:10）
- 根因：JSch 的密钥交换/签名/密钥对算法是**按类名反射加载**的（`JSch.setConfig("ecdh-sha2-nistp256", "com.jcraft.jsch.DHEC256")`
  + 运行时 `Class.forName`）。release 开了 minify，R8 从调用图看不到这些类，把它们全裁掉了，
  只留下 dex 里的类名字符串常量 → 运行时 ClassNotFoundException。
- 排查手法：解出 APK 的 classes*.dex，`grep -a "Lcom/jcraft/jsch/DHEC256;"`，没有匹配即被裁剪
  （对比：字符串 `com.jcraft.jsch.DHEC256` 还在，很容易误判为类存在——要看类型描述符 `L...;`）。
- 修复：app/proguard-rules.pro 增加
  `-keep class com.jcraft.jsch.** { *; }` / `-keep class com.jcraft.jzlib.** { *; }` 及对应 `-dontwarn`。
- 教训：凡"按类名反射/服务发现"加载的库（JSch 算法、SLF4J 绑定、ServiceLoader），配 R8 时必须整包 keep，
  不能只 keep 直接引用的类。
- 顺带验证：`java.util.Base64` 已被 desugar 成 `j$.util.Base64`（API 21 可用），GitSsh 里的 Base64 没有低版本兼容问题。
- 重建后 APK 13,195,277 字节（比修复前 +25KB），签名不变，DHEC256/DHEC384/DHEC521/DHECN/DHG14/DH25519/DH448/
  DH25519SNTRUP761/SignatureEdDSA/KeyPairGenEdDSA 均已进 dex。

### Git 同步：静默失败修复 + 保存即提交 / 启动即拉取（18:35）
- 用户反馈：「忘了填作者信息时自动同步和手动推送都静默失败，没有任何提示」；另要求保存后立刻自动提交、启动后立刻自动拉取。
- 关键排查结论（实测，别再猜）：
  - **JGit 5.13 对空作者不报错**。用 jgit jar 直跑验证：name/email 传 ""、"   " 都能 commit 成功。
    而且 AppSettings.getGitAuthorName/Email() 一直有 fallback（Markor for Android / markor@localhost），所以作者为空根本不会让提交失败。
  - **真正的静默点**：`MainActivity.onPause()` 调 `GitNotebook.detach()`，之后所有 `postMessage` 的 `_uiRef` 为 null →
    消息直接丢弃。而设置页（SettingsActivity）里的「同步/拉取/推送」按钮恰恰是在 MainActivity 暂停时点的 → 完全无提示。
    另外 `run()` 里「仓库目录为空」和「BUSY」两处早退也是无声的。
- 改动：
  - `GitNotebook`：新增静态 `_appContext`（remember() 记录）作为提示兜底出口；`postMessage`/`postConflict` 在没有挂载 Ui 时用 Toast 兜底。
  - `run()`：非静默请求在「不是 git 仓库」/「上一次操作还在跑」时明确提示（R.string.git_not_a_repository / git_sync_busy）；
    自动请求（onError==null）保持安静。
  - 新增 `warnIfAuthorMissing()`（一次进程只提示一次）：作者没填就提示 + 写进「最近同步」，不拦同步。
  - `onFileSystemChanged`：现在**立刻提交**（commitOnSave，不等 3s 防抖），远端拉+推仍走 3s 防抖。
  - 新增 `onAppStarted(context)`：冷启动立刻 pullOnly，`ApplicationObject.onCreate` 里调用（GitSyncJob.schedule 之后）。
  - `AppSettings.isGitAuthorConfigured()`：判断用户是否真的填了（不走 fallback）。
  - `SettingsActivity`：作者名/邮箱偏好显示实际值，未设置时显示 git_author_not_set。
  - 新增字符串 git_sync_busy / git_author_missing / git_author_not_set（values + values-zh-rCN 都加了）。

### 编辑器「从文末开始」开关失效（19:16）
- 现象：设置 → 编辑模式 →「从文末开始」默认显示未勾选，实际总是从文末开始，勾选/取消都没反应。
- 根因（两处）：
  1. `AppSettings.isEditorStartOnBotttom()`（注意名字里是 Botttom，三个 t）**全项目零调用**——开关根本没接进逻辑。
     真正的落点在 `DocumentEditAndViewFragment.onFragmentFirstTimeVisible()`：
     `_appSettings.getLastEditPosition(path, _hlEditor.length())`，兜底值写死为文末。
  2. 默认值不一致：preferences_master.xml 里 `android:defaultValue="false"`，AppSettings 兜底却是 `true`。
- 修复：
  - XML 默认值改 `true`（保持"从文末开始"这个既有行为，同时让勾选框显示与真实行为一致）。
  - 落点改为「记忆优先」：`getLastEditPosition(path, isEditorStartOnBotttom() ? length() : 0)`
    —— 有上次编辑位置就用记忆，只有没记忆（首次打开）的文件才由开关决定文末/开头。
  - 因此「恢复上次编辑滚动位置」那段保留不动，跟记忆是一套。
- 用户明确要的语义：**记忆优先，开关只对没记忆的文件生效**（19:23 确认）。
- 19:36 用户反馈「还是最下边」。再查一轮确认链路没问题（点击文件传的 lineNumber 是 null，
  不会走 hasLineNumber 分支；prefs 文件名 app 与设置页一致；setDefaultValues 从未调用）。
  真正的坑：项目**没有调用 PreferenceManager.setDefaultValues**，所以 XML 的 android:defaultValue
  **只影响勾选框显示、不会写进 SharedPreferences**；用户没拨过开关时，代码读到的是 AppSettings 里的兜底值。
  两边不一致（XML false / 代码 true）就是「显示未勾选、行为却是文末」的来源。
- 最终定案：以勾选框为唯一事实来源 → XML 与 AppSettings 兜底都设为 **false**（未勾选=从开头开始）。
  并在 isEditorStartOnBotttom() 上写清这个约束，避免以后再改坏一边。
- 提醒用户的测试陷阱：老 build 打开过的文件已经把「文末」写成了记忆，记忆优先会盖掉开关，
  必须用**装了新包之后新建**的文件验证。
