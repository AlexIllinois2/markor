## Markor 界面续改：去掉标题 + 修"僵尸行" bug

用户反馈：「现在咋满是bug了？哪哪都点不动 要么点出来的是个风马牛不相及的东西」+「标题栏去掉 markor 这个标题」。

### 1. 标题栏去掉标题（用户明确需求）
`setDisplayShowTitleEnabled(false)` **无效** —— 因为 `GsActivityBase.setTitle()` 覆写后会直接调 `Toolbar.setTitle()`，
绕过了 AppCompat 的显示开关。正确做法：在 `GsActivityBase` 加 `_toolbarTitleEnabled` 开关 +
`setToolbarTitleEnabled(boolean)`（关闭时顺手把已有标题清空），MainActivity.onCreate 里关闭。
同时去掉 `main__activity.xml` 工具栏上的 `app:title="@string/app_name"`。
结果：主界面顶栏只剩右侧操作图标；多选时副标题 `( 1 / 2 )` 仍显示（由 `GsFileBrowserFragment` 直接设 subtitle）。

### 2. 真正的大 bug：列表"僵尸行"
现象：文件列表里**某一行突然没有白色卡片底色、文字变灰、点击完全没反应**；点别的行还会打开不相干的文件。
定位过程：截图逐像素采样（选中/普通/页底 分别为 #F2DCE0 / #FFFFFF / #F2F3F8），发现该行背景**完全没画**（等于页底色），
再用 `setprop debug.layout true` 看布局边界确认行本身存在、只是背景缺失。
根因：行的背景是 StateListDrawable（`ui__file__item__selection_background`）+ `notifyItemChanged` 触发的
RecyclerView item 动画叠加，出现残留/状态错乱的行。
修复：
- `GsFileBrowserFragment.onViewCreated`：`_recyclerList.setItemAnimator(null)`（卡片列表本来也不需要条目动画）。
- `GsFileBrowserListAdapter.applyRowBackground(view, selected)`：背景改为**代码直接绘制**
  —— `GradientDrawable`（选中 = accent_wash + 1.5dp accent_stroke；常态 = card）+ `RippleDrawable`（mask 同圆角，保留按压反馈）。
- 删掉之前 `setActivated()` 的写法；布局里背景换成静态 `bg_file_item_card.xml` 兜底。
修复后连续验证：点击打开文件、长按多选、返回、逐级跳目录，均无缺底色行，点击即时生效。

  查端口：`MuMuManager.exe info -v 1`（本次是 `127.0.0.1:16416`）。
  正确重启方式：`MuMuManager.exe control -v 1 shutdown` 然后 `control -v 1 launch`，再 `adb connect 127.0.0.1:<port>`。

### 5. 预览模式"纸张化"（编辑态与预览态统一）
现象：编辑态是一张带圆角的纸，切到预览（WebView）却变成满铺方角底色，像两个应用拼起来。
两个坑：
1. `WebView` 自身的不透明底色会盖住背景 drawable —— 圆角画在 WebView 上无效。
   → 改 `document__fragment_view.xml`：`FrameLayout(id=document__fragment_view_root)` 包
   `DraggableScrollbarWebView(id=document__fragment_view_webview)`，圆角纸画在**容器**上，
   容器 `setClipToOutline(true)` 裁剪，WebView `setBackgroundColor(TRANSPARENT)`。
   新增字段 `_webViewRoot`，`setViewModeVisibility` 里的 `fadeInOut` 目标同步换成容器。
2. 深色 HTML 样式里写死 `background-color:#303030`（PDF 导出依赖，不能删）。
   → `TextConverterBase.convertMarkupShowInWebView` 中**仅当 `!lightMode`** 时注入
   `html,body{background-color:transparent !important;}`；导出（lightMode=true）不注入，避免打印白字白底。
实测：深色/浅色预览纸色都与编辑态一致。

## 13. 编辑时上滑收底栏 + 收键盘（2026-10-22 20:10）

需求：编辑（弹软键盘）时上滑 → 底栏自动隐藏 + 键盘隐藏；下滑 → 底栏滑回。

实现：
- `DraggableScrollbarScrollView`：新增 `OnScrollPositionChangedListener`（挂 `onScrollChanged`，
  API 21 可用）+ `isUserTouching()`。触摸态在 `onInterceptTouchEvent`（DOWN）和
  `onTouchEvent`（UP/CANCEL）里维护。
- `DocumentEditAndViewFragment.setupChromeAutoHide()`：位移阈值 14dp、冷却 420ms；
  **必须先判 `isUserTouching()`**——`onScrollChanged` 对程序性滚动（聚焦把光标滚进视野、
  恢复上次位置）同样回调，不区分的话一进编辑器就把底栏和键盘一起收掉（第一版就踩了这个坑）。
  上滑（delta>0）→ `showSoftKeyboard(false)` + `setBottomNavAutoHidden(true)`；
  下滑只还原底栏，不主动弹键盘（弹了会挡正文）。
- `MainActivity.setBottomNavAutoHidden()`：`translationY = navHeight + marginBottom + 8dp`
  滑出屏幕，同时 `ValueAnimator` 把 ViewPager 的 `bottomMargin` 在 0 ↔ `bottom_nav_space` 之间过渡，
  正文才铺到屏幕底。`onViewPagerPageSelected` 复位；`onDestroyView` 也复位（免得隐藏态被带到别的页面）。
- 关键坑：`setOnTouchListener` 挂在 ScrollView 上**收不到 ACTION_DOWN**（被子 View 消费），
  所以判定要下沉到自定义 View 的拦截/触摸方法里。

实测（MuMu，`127.0.0.1:16416`）：进编辑器不再误收底栏；上滑后底栏消失、格式栏贴底、
`dumpsys input_method` 的 `mInputShown` 由 true 变 false；下滑底栏弹回；无异常日志。

环境备注：
- 本机模拟器 Sogou 输入法 `mInputShown=true` 但画面不渲染键盘，验证键盘要用
  `dumpsys input_method | grep mInputShown`，不能只看截图。
- 装包：debug 与已安装的 release 签名冲突（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`），
  测试直接用 `assembleRelease` 的包；`adb install` 的路径要写 `D:/...`，`/d/...` 会 stat 失败。

## 14. 设置页瘦身：去掉"起始文件夹" + 二级页改成懒加载（2026-10-22 21:15）

### 需求
1. 设置-通用-杂项设置里删掉"应用起始文件夹"（文件页早就锁在笔记本目录里了，这项没意义）。
2. 设置页进入太慢。

### 删掉起始文件夹
- `preferences_general.xml` 里移除 `pref_key__app_start_folder` 的 ListPreference。
- `MainActivity` 起始目录直接取 `_appSettings.getNotebookDirectory()`，不再读这个偏好。
- `AppSettings.getAppStartupFolderMenuId()` 删除（`getFolderToLoadByMenuId()` 保留，是通用工具）。

### 设置页为什么会慢（实测拆解）
用临时计时日志（tag `MSPERF`，测完已删）量出来的：
| 阶段 | 拆分前 | 拆分后 |
|---|---|---|
| inflate_xml（冷） | 58–241ms | **10ms** |
| inflate_xml（热） | 27–35ms | 10ms 以内 |
| first_layout | ~0（热）/ 244–443ms（冷） | 同量级（RecyclerView 首次建 view holder 的固有开销）|

根因：`preferences_master.xml` 里 12 个入口写成 `<PreferenceScreen>`，把子页 **70 多个 Preference 一次性全 inflate**，而顶层其实只有 14 行。

### 拆分做法
- 顶层 `preferences_master.xml` 只留 14 行"入口"，入口改成普通 `<Preference android:key="nav_*">`。
- 10 个子页各自一个 XML：`preferences_general/other/edit/view/format_{markdown,todo,wikitext,plaintext,asciidoc,orgmode}.xml`。
  "编辑"页里嵌套的"基础颜色方案"仍留在同一个 XML 内，行为不变。
- `SettingsActivity`：新增 `showSubScreen(xmlRes, title)`（replace + addToBackStack）；
  `SettingsFragmentMaster.newInstance(xmlRes, title)` 用 arguments 存 xml/title，`getPreferenceResourceForInflation()` 读它；
  `onPreferenceClicked` 里 `nav_*` → `subScreenXmlFor(key)` → 打开子页；标题用被点那一行的 title 立刻设置。
- `onBackPressed` 改成看**当前可见**的面包屑：先 `canGoBack()`（子页内再叠一层的情况），再 `popBackStack()`，最后才 finish。

### 顺带修掉的两处"白干活"
- `updatePreferenceIcons` 原来会 `postDelayed` 5 次（200ms/2s/10s/20s/100s）把整棵树的图标重新着色 ——
  既造成首帧之后的黑图标闪烁和反复重绘，又在 2/10/20/100 秒各重扫一遍。现在改成在
  `onCreatePreferences` 里一次性上色（首帧就是最终颜色），`onViewCreated` 只留一次兜底 post。
- `onResume` 里 `doUpdatePreferences()` 和 `onPreferenceScreenChangedPriv()` 各调一次（同一份刷新跑两遍），
  删掉前者。
